# Contributing

Thanks for helping improve `selfhosted-sentry-mcp`.

## Setup

Requires Node.js 20 or later (`engines` in `package.json`).

```bash
git clone https://github.com/HieuAnh87/sentry-selfhosted-mcp.git
cd sentry-selfhosted-mcp
npm install
```

`npm install` triggers the `prepare` hook, which runs a build — so you get a compiled `build/` directory for free.

## Build

```bash
npm run build     # tsc, then chmod +x build/index.js
npm run watch     # tsc --watch while editing
```

The `chmod` step matters: `build/index.js` is the package `bin` entry and must stay executable.

## Test

```bash
npm test                        # full suite (Node's built-in test runner)
npm run test:smoke              # smoke flow only
node --test test/tools.test.js  # one file
```

`test/tools.test.js` asserts the exported tool list, currently fixed at 24 tools. HTTP is stubbed with `nock`; tests never contact a real Sentry instance.

Run the tool-surface test before opening a PR that touches tools:

```bash
node --test test/tools.test.js
```

## Manual checks

Drive the server interactively with the MCP inspector:

```bash
npm run inspector
```

It needs `SENTRY_URL`, `SENTRY_AUTH_TOKEN` and `SENTRY_ORG_SLUG` in the environment; the server validates all three at startup and exits if any is missing.

## Ground rules

### `src/**` is the source of truth — never edit `build/**`

`build/` is generated by `tsc`. Any edit there is silently destroyed by the next build. Change the TypeScript in `src/`, then rebuild. Do not commit `build/` changes as if they were source.

### Tool names and input schemas are a public contract

Every tool name and parameter in this server is wired into users' MCP client configs and agent prompts. Renaming a tool, renaming a parameter, making an optional parameter required, or narrowing an enum **breaks working setups with no error message the user can act on**.

So:

- Additive changes (new optional parameter, new tool, widened enum) are fine.
- Breaking changes need a clear reason, a note in `CHANGELOG.md`, and a major version bump.
- If you must replace a tool, keep the old name working for at least one release.

### Adding or changing a tool

Three places must stay in sync, or the server will list a tool it cannot call:

1. `src/tools/<area>.ts` — the `ToolDefinition` and its handler
2. `src/server.ts` — the `TOOLS` array **and** the `switch` in `setupToolHandlers`
3. `test/tools.test.js` — the expected tool list and count

Add the argument type guard in `src/helpers/index.ts` too; handlers validate their input before doing anything.

### Do not widen output without filters

This project exists to keep Sentry responses inside an agent's context window. Returning a raw Sentry payload defeats the entire point.

Before returning a large object, route it through the helpers in `src/helpers/`: `truncateResponse`, `filterObjectFields`, `grepFilter`, `truncateStackTraces`, or the `extractEssential*` functions. New tools that hit event endpoints should support at least a `limit` or `grep_pattern`.

The 50,000-token ceiling lives in `MAX_TOKENS` in `src/config.ts`. `raw_sentry_api`'s refusal path above that limit is deliberate — preserve it.

### Never commit real credentials

No real `SENTRY_AUTH_TOKEN` values and no real Sentry hostnames in code, tests, docs or examples. Use placeholders like `https://your-sentry-instance.com` and `<your-token>`. See [SECURITY.md](SECURITY.md).

## Conventions

- **ESM with explicit `.js` extensions** in TypeScript imports (`import { x } from './helpers/index.js'`) — required by Node16 module resolution. Importing without the extension will compile and then fail at runtime.
- `src/index.ts` is intentionally a thin re-export of `./server.js`; keep it that way.
- Handlers return `{ content: [{ type: 'text', text: ... }] }`; errors go through `handleToolError`, and invalid arguments throw `McpError(ErrorCode.InvalidParams, ...)`.

## Pull requests

Before opening one:

1. `npm run build` succeeds
2. `npm test` passes
3. Tool changes are reflected in `src/server.ts`, `test/tools.test.js`, the README tool tables and the landing page tool list in `docs/index.html`
4. User-visible changes have a `CHANGELOG.md` entry under `## [Unreleased]`

Keep diffs focused. Describe what changed and why, and call out anything that alters a tool contract.

## Reporting bugs

Open an issue at https://github.com/HieuAnh87/sentry-selfhosted-mcp/issues with the version, your Node.js version, the tool involved, what you expected, and what happened. Redact tokens, real hostnames and any user data from Sentry payloads before pasting them.

Security vulnerabilities go through [SECURITY.md](SECURITY.md) instead — not the public issue tracker.
